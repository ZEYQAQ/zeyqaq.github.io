hive是基于hadoop的，数据存储在 HDFS（Hadoop Distributed File System，Hadoop 分布式文件系统）上，底层表本质上是 HDFS 上的目录或文件。

比如过去企业里每个人点击了什么任务，更换了多少次头像这种暂时没啥效益的数据一般会落盘存储桶，还有更多非结构化的文件、数据，可以看作纯数据湖。纯粹结构化的内容是数据仓库。

Hive 表既不是传统意义上的纯数据湖，也不是传统的关系型数仓，而是连接两者的关键桥梁，通常被称为数据湖仓（Lakehouse）的核心组件。其中hive表有两部分，一部分就是纯数据湖的效果，存储在hdfs上的各种数据；另一部分是一组mysql表，存储了Hive 表名叫什么、有哪些字段、字段是什么类型、数据在分布式文件系统的哪个具体文件夹下，等等，这个组件被称为 Hive Metastore。

所以当我们有需要对数据进行分析时，就可以先检索一下结构化的表格，看看有什么字段是存在于数据湖的，相关性强就可以制作表格。

查询 Hive 表主要使用 HiveQL (Hive Query Language)，这是一种类似于传统 SQL 的查询语言。hive sql的外观像 SQL，但查询对象、执行引擎和语法细节不一样。

对于我分析hive表，一般直接使用agent工具去写hsql，prompt一般是 表link+诉求+查询器link

比如

```
我该如何用这个表（HiveTable:///xxx_devops/dwm_process_job@0），查询某个流水线中，这种跳过的节点操作人？你可以在内部查询编辑器（查询器link））里运行 SQL 排查。
```

而有时候我们需要沉淀hsql到具体的仪表盘，以实现可视化。这时候可以用 Tableau / Power BI，在字节也有类似的bi软件。我本来是想沉淀一篇如何制作bi仪表盘的方法，但是现在看，ai已经可以通过自然语言生成可用的仪表，所以不再赘述。

对于同样很强的clickhouse，hive更多的是处理吞吐量大但不要求时效性的离线任务，ck则是要求在秒级或者毫秒级返回查询结果。ck更多是根据日期地域等维度查询量化的指标，比如查询华东地区的销售额。再说es，虽然ck和es都可以拿来存日志，但是es一般针对关键字检索、模糊匹配的，要找固定几行日志的场景，而ck则是针对数据量巨大（可到PB级别）的大盘统计、指标监控、漏斗分析等聚合计算，而不是搜具体的某一句文本。
